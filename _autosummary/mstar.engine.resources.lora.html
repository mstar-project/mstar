class mstar.engine.resources.lora.LoraSpec(resource_key, nodes, num_layers=<factory>, targets=<factory>, module_map=<factory>, max_slots=4, max_rank=16, cpu_capacity=16, adapters=<factory>, runtime_updates=False, runtime_update_timeout_s=120.0, adapter_digests=<factory>, dtype=None, backend='auto', convert_keys=None, ignored_modules=<factory>, dropped_targets=<factory>, declare=None)[source]#

Bases: NodeResourceSpec

Per-request LoRA adapters for the linears named in targets.

max_slots adapters are resident on the device at once, beside a zero adapter that base-model rows use, and up to cpu_capacity are kept pinned on the host. adapters maps the names requests ask for to safetensors paths. module_map places each checkpoint module on a target; a node’s spec comes from module_lora_spec (mstar.model.components.lora.modules), whose LoraMap is what binds the node’s modules, and a pool built with any other resolver is refused at bind. convert_keys rewrites a model-native checkpoint layout first. declare gives num_layers, targets, module_map and ignored_modules in place of passing them, on their first read: module_lora_spec walks a node’s modules there, which a deployment that never builds the spec skips.

Opt-in (NodeResourceSpec.opt_in): built only for a deployment whose serving config has a resources: lora: block. One spec covers every node an adapter reaches (an LLM and its vision tower), and each node gets a pool of its own (per_node): the nodes may sit in different lockstep instances, whose ranks must make the same slot decisions.

class mstar.engine.resources.lora.LoraTarget(in_features, out_slices, parallel='column', slice_names=(), slice_units=None, slice_packs=None, slice_align=None, layers=None, node=None, kind='linear', per_segment=False, token_fold=1, experts=1, expert_split=None)[source]#

Bases: object

One family of linears an adapter may touch, e.g. every layer’s fused qkv_proj.

Shapes are the unsharded linear’s. out_slices lists the output widths of a fused projection in order ((q, k, v)); each slice has its own A and B, named in a checkpoint by the stacked-shard id in slice_names. A single linear has one slice.

parallel says how the base linear is split across tensor-parallel ranks:

  • "column": output rows are split, so A is replicated and B is sharded by output rows of each slice. The delta lands on this rank’s rows of the output.

  • "row": input columns are split, so A is sharded along the input and B replicated. x @ A_r^T is then a partial sum over this rank’s input columns, and so is the expanded delta: add it to the partial base output before the layer’s all-reduce, which sums both. LoRA adds no collective.

  • "none": every rank holds the whole adapter and adds the whole delta to an output that is already whole (after the base layer’s own collective).

slice_units counts the shardable units (heads) of each slice. A slice with fewer units than ranks is replicated across groups of ranks rather than split, as QKVParallelLinear does with GQA’s K/V heads. None treats every row as a unit.

slice_packs names checkpoint modules that pack several slices into one tensor: a gated delta-net’s in_proj_qkv is [q | k | v], three outputs the base shards across ranks on their own. Such a module has one A, which each of its slices takes, and a B whose rows are those slices’ in order. A pack named None is the module itself as a checkpoint stores it fused, with no stacked-shard id.

slice_align rounds each slice’s rank-local width up to a multiple, for a base linear that pads its fused output per rank so the next slice starts aligned. The padding rows follow the slice’s own, and B is zero there.

layers names the stack layer indices this target exists on (a hybrid stack has attention on some layers only); None means all of the spec’s num_layers.

node is the graph node the target’s linears run on, which a spec over several nodes names for every target (each node’s pool holds its own, LoraSpec.for_node); None for a spec over one node.

kind="embedding" is a token embedding: in_features is the vocabulary, a row’s input is its token id, and the shrink gathers A’s column for it (x @ A^T of the token’s one-hot), as PEFT’s lora_embedding_A / _B define it.

Which rows the linear sees, for the per-row adapter choice: one per token of the step (the default), one per segment (per_segment, e.g. an LM head over each row’s last token), or one per token_fold consecutive tokens of a segment (a patch merger that folds 2x2 patches into one row).

experts counts the groups of the weight: 1 for a linear, E for one stacked parameter of an MoE layer’s routed experts ([E, out, in]), where each row runs its token’s slot’s adapter on the expert the router picked for it. Each expert has its own A and B per slice, named in a checkpoint by the stacked-shard id "<slice>:<expert>" ("gate:3"). expert_split is (first, count) of the experts one rank’s module holds when expert parallelism splits them; None when it holds every expert.

Whether a deployment’s YAML turns LoRA on (a resources: lora: block), with or without adapters named in it: adapters may also be loaded at runtime. A resources: value that is not a mapping turns nothing on: the conductor’s validate_deployment reports it with the deployment’s other problems.

Modules

backend

Kernels that add a batch's LoRA deltas: shrink h = x @ A^T, then expand y += s * h @ B^T.

checkpoint

Reading LoRA checkpoints: shared by the static merge and the per-request adapter pool.

config

What a model declares about per-request LoRA adapters.

identity

Which weights an adapter name stands for, as the prefix cache keys them.

ops

The LoRA shrink and expand as custom ops, so torch.compile sees one opaque node each, and lora_apply_, the two as one op, which is what a linear target runs; lora_experts_apply_ is an experts target's shrink and expands over combined ids.

pool

Per-request LoRA adapters resident in a fixed set of device slots.

serving

The serving config's LoRA adapters, resolved once before the conductor starts.

store

The host tier of the adapter pool: adapters read, sharded for this rank, and pinned.
