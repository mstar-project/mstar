mstar.engine.resources.recurrent.config#

What a model declares about a pool of recurrent state.

Kept free of the manager so declaring a step does not import a backend. The pool is ignorant of what the state means: a slot is a fixed number of bytes per layer, so capacity is a slot count and a fork is a fixed-size copy.

class mstar.engine.resources.recurrent.config.DeltaNetGeometry(num_k_heads, num_v_heads, head_k_dim, head_v_dim, conv_kernel_size)[source]#

Bases: RecurrentGeometry

Head geometry of the delta-net family: gated delta rule (Qwen3.5, Qwen3-Next) and Kimi delta attention (Kimi Linear, GLM-5.3).

Both carry a K-last [HV, V, K] state matrix (FlashInfer’s pool layout) and a conv window holding every tap but the current token’s. to_blocks and from_blocks are inverses, so a backend reads its geometry off the pool.

class mstar.engine.resources.recurrent.config.RecurrentStep(segments=None, pre_forks=(), post_forks=())[source]#

Bases: ResourceStep

One step’s work against the pool.

No commit flag, unlike KVStep: a backend writes the pool in place, so a non-committing reader needs two labels, reading one and writing another.

Forks mirror KVStep’s: (from_label, to_label) pairs, reserved at admit and copied at plan (pre) or commit (post).
