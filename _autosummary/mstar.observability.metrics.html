mstar.observability.metrics#

Prometheus metrics for the API server: --enable-metrics and GET /metrics.

Requests are counted where they leave APIServer, which /generate, /generate/ws, the OpenAI routes, the Rust-frontend bridge and the Dynamo bridge all go through. Requests the HTTP frontend refuses before that (a missing API key, a body over the limit, a bad form) are counted by route and status in mstar_http_refusals_total. Each family carries the deployment’s model_name; every other label takes values from a fixed set.

Only the API server process imports prometheus_client and renders /metrics. Other processes (data worker, conductor, workers) send plain numbers on messages they already send the API server, plus the conductor’s periodic status message, and the API server records them here; no multiprocess directory, which would only aggregate one host. Families whose values come from another process are defined in catalog.

prometheus_client is optional (pip install 'mstar[metrics]') and only needed when metrics are on.

class mstar.observability.metrics.RefusalMiddleware(app, metrics, routes)[source]#

Bases: object

Counts mstar_http_refusals_total for the Python frontend: every HTTP response with a 4xx status for a request that never reached APIServer.submit_request (mark_submitted()). A request that was submitted and then failed is counted by mstar_requests_total instead.

Sits outside the API key and body limit middlewares (their 401 and 413 are sent before routing) and inside CORS (a preflight is not a request). WebSocket handshakes are not counted. With metrics off it only checks metrics() for None.
