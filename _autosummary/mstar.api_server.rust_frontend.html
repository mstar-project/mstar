mstar.api_server.rust_frontend#

The Rust axum frontend in front of APIServer.

mstar-server (rust/server/) owns the HTTP surface — routes, OpenAI translation, SSE/NDJSON streaming, uploads, CORS — and speaks a flattened msgpack protocol over the Rust ZMQ transport to this bridge, which drives the existing Python data plane (APIServer.submit_request / iter_result_chunks / abort_submission; preprocessing and the conductor protocol are untouched):

frontend -> bridge: {t:”submit”, rid, sub, text, file_paths,

input_modalities, output_modalities, model_kwargs, prompt_parts, streaming, accepts_chunks, report_usage}

{t:”abort”, rid, sub}
{t:”ping”, rid, sub}
{t:”metrics”, rid, sub, refusals:{route, status, count}}
{t:”check_ref_audio”, rid, sub, path, decoder, bare}
{t:”voices”, rid, sub}
{t:”windows”, rid, sub, op, plan, …}
{t:”live”, rid, sub, op, call, …, stream?, audio?(bin)}
{t:”end_of_turn”, rid, sub, audio(bin)}
{t:”lora”, rid, sub, op, lora_name, lora_path?}
bridge -> frontend: {t:”chunk”, rid, sub, modality, data(bin), metadata}
{t:”chunks”, subs, modalities, payloads(bin), metadatas}
{t:”err”, rid, sub, msg} | {t:”done”, rid, sub}
{t:”pong”, rid, sub}
{t:”metrics”, rid, sub, data(bin), metadata}
{t:”checked”, rid, sub, error?, status?}
{t:”voices”, rid, sub, metadata:{voices?}}
{t:”windows”, rid, sub, metadata:{duration, single, windows} | {error}}
{t:”live”, rid, sub, metadata:{taking | accepted | rejected | error, status, error_id?}}
{t:”end_of_turn”, rid, sub, metadata:{p} | {error}}
{t:”lora”, rid, sub, metadata:{text} | {error:{status, message}}}
{t:”served”, adapters} (unsolicited, on every change)

A live request is one operation on a /generate/ws live call, the submission call names: taking (taking_input), append (stream_input) or reject (reject_input). An append the model finds late is sent later as a chunk (modality late) on the socket’s notice route, its tag echoed in the metadata.

A windows request is one operation on a transcription upload’s WindowPlanner (serving_transcriptions), kept here under the frontend’s plan id: plan makes it (and decodes an upload that will be windowed), fixed, at and cut cut windows, and close deletes the upload and its windows, with no reply. The model’s own loader decodes the upload, which no Rust decoder matches.

A metrics request carries the frontend’s cumulative refusal counts as three parallel lists (route template, status, count), which the API server exports as mstar_http_refusals_total. The reply is what GET /metrics serves on the Python frontend: the text rendered from APIServer.metrics with its content_type in metadata, or empty metadata when metrics are off (a 404; the counts are then ignored).

chunks carries many submissions’ chunks as parallel lists, in order: the API server’s message thread hands the bridge every chunk it drained in one pass (APIServer.relay_chunks_to), so a decode step costs one message rather than one per request. Only a submit that sets accepts_chunks gets them, so a frontend binary older than this bridge still gets chunk``s. A submission's error chunk, and anything its handler finds unrelayed at the end, always goes out as ``chunk.

A submit that sets report_usage (a chat) gets a last chunk of modality usage before done: its token counts and finish reason in metadata (APIServer.submit_request’s report_usage).

sub names one submission and is never reused. A client may resubmit its rid as soon as it drops a stream, and that stream’s done or late chunks can cross the retry, so everything about a submission is addressed by sub. The frontend refuses a rid still in flight with a 409 itself and sends a dropped stream’s abort before it frees the rid, so the abort arrives here before the retry’s submit.

The submit shape is APIServer.submit_request’s signature verbatim — the protocol was designed by flattening it. prompt_parts travels for a chat only, one map of PromptPart’s fields per part. The bridge mesh lives in its own socket dir (private to the frontend/bridge pair), so entity names never collide with the conductor/worker mesh.

mstar-serve runs the mstar-server binary + this loop in place of uvicorn.run (unless --python-frontend). Everything else in the process (preprocess worker, conductor spawn, tensor transport) is identical. The frontend enforces the API key (--api-key / MSTAR_API_KEY) itself; the bridge socket is private to the pair.

mstar.api_server.rust_frontend.find_server_binary(explicit=None, rust_dir=CHECKOUT_RUST)[source]#

Resolve the mstar-server binary: explicit arg, MSTAR_SERVER_BIN, the running environment’s scripts directory (where a Linux wheel installs it, also when the venv is not activated), $PATH, then the in-repo release build. The scripts directory goes before $PATH so another environment’s older binary never serves this one’s bridge.

In a checkout, a binary built from other sources than rust_dir is skipped, or used with a warning when named by the arg or the variable. Raises FileNotFoundError when there is none, RuntimeError when all are stale.
