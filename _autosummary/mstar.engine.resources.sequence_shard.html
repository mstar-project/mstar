mstar.engine.resources.sequence_shard#

Sequence parallelism: whether a step’s tokens split over a node’s SP ranks, and how attention reaches the tokens it needs when they do.

A node’s SP ranks share each step one of two ways. Its tokens are split (each rank runs the token-local layers on its share) or copied (every rank runs them all). The sequence shard resource (SeqShardSpec) decides which, per step, from the step the model declares, and gives each listed label its per-rank ranges (SeqRange): contiguous, or on a node whose attention runs the ring, striped by KV position. A model brackets its layer stack with scatter / gather on that resource; nothing else in model code changes.

The attention resources over the node depend on it (shard_key, taken in their specs’ derive) and pick an exchange per label from its plan: for a split label, the shard’s exchange over their storage; for a copied one, what attends it at the node’s head geometry. The exchanges are the functions at the bottom of this module, each wrapped around the resource’s own run:

  • ulysses: one all-to-all from tokens to heads, run, and one back (head-stored KV, a cacheless attention planning a label the shard lists, RaggedAttentionSpec.labels, or a recurrent layer’s prompt rows);

  • all_gather: every rank’s q, k and v gathered, run as on a copied step, this rank’s share of the output (KV stored by position, context_parallel);

  • ring: a striped label’s own tokens, whose K/V this rank stores, run on them with their indices in the step; the plan passes queries round the partners (KV stored by position, RingAttentionWrapper);

  • head_slice: a copied step at a tp * sp head geometry: this rank’s heads, run, gather the heads;

  • sharded_key_merge: copied queries over split keys (cacheless cross-attention): each rank’s partial with its log-sum-exp, merged;

  • kv_gather: every rank’s k and v gathered, run writes them and attends this rank’s queries (KV every rank stores whole: a sliding-window attention’s layers of a pool stored by position).

A recurrent layer’s resource takes its conv’s left context from the earlier ranks (conv_halo), and its prompt rows through ulysses where its heads split over the SP ranks or else state_passing, the state a row enters a rank with (the spec picks from its head counts).

sequence_parallel_refusals is what a node on SP ranks may not declare; the engine and validate_deployment both run it.

class mstar.engine.resources.sequence_shard.SeqShardSpec(resource_key, nodes, labels, axis, walks=None, *, min_tokens=0, exchange='auto', exchanges=True)[source]#

Bases: NodeResourceSpec

A node’s steps split over its SP ranks, or copied.

labels are the step labels whose tokens split. axis 0 splits a label’s packed tokens into contiguous ranges; axis 1 splits each row of a [B, S, ...] layout alike (every row of a label one length). walks lists the walks that may split (None: every walk); the others plan copied. A step splits only when it is not one token a row, its listed tokens are at least max(sp, min_tokens), and every listed label has at least sp tokens (a row, for axis 1), so no rank gets an empty range. min_tokens is a resources: override, a floor above the one the node sets itself (below).

exchange, also a resources: override, is how a split step’s tokens reach the node’s paged attentions, from the storage of the node’s pools (NodeResourceSpec.storage):

  • auto (the default): Ulysses over KV stored by head; over KV stored by position (context_parallel) the node runs copied, so splitting there is the deployment’s to opt into;

  • ulysses (by head), all_gather or ring (by position; the ring stripes each step by stored position): split;

  • none: never split.

Where the node splits, a resource over state every rank stores whole takes its own exchange whatever this one is: a window attention gathers the step’s keys (kv_gather), a recurrent layer the one its head counts allow. So does a ragged attention, by Ulysses wherever it plans a label this shard lists (RaggedAttentionSpec.labels); a shard that never splits stops them all splitting.

exchanges=False declares that no op on the node mixes a listed label’s units (a video decoder’s independent clips): nothing exchanges them, so the node needs no attention, and a rank may get an empty range (fewer units than ranks still splits; gather takes it).

The attention and position resources on the node take this as a dependency in their own derive. A model declares no step for it: its step is the node’s segments and combined_labels (Resource.steps_from_segments), so a combined plan label gets a range over its sources too; at one SP rank it plans copied at no cost.

Two fields are derived from exchange and the resources on its nodes (derive), from their hooks alone: splits, whether the node’s steps may split (not where exchange resolves to none, or where no resource there takes split steps and exchanges is True); stripe_pool, the pool a ring attention reads, by whose stored positions each step is striped; and eager, whether a resource there splits its steps eagerly only (NodeResourceSpec.splits_eagerly: a ring, kv_gather, a recurrent layer). Such a node never splits a captured step: at load the shard sets, for each walk it splits, a floor one past that walk’s largest captured bucket (SequenceShard.check_captures), the same on every rank, so a step that fits a captured bucket runs copied in its graph and a bigger one runs eagerly and splits (min_tokens raises the floor, never lowers it).

class mstar.engine.resources.sequence_shard.SequenceShard(labels, axis, walks, min_tokens, group, splits=True, stripe_pool=None, device=torch.device('cpu'), exchanges=True, eager=False)[source]#

Bases: Resource

Plans each step split or copied (SeqShardSpec) and brackets the layer stack with scatter / gather. Holds no per-request state and no device buffers: its plan is from the declared step, the lease and (striped) the pool’s plan, the same on every rank; a striped step’s order is copied to the device with it. Off its defaults: prefix_skip_safe (it plans from the step a prefix hit already trimmed), supports_preplan (its dependents pre-plan), supports_context_parallel (a striped shard reads a placed pool’s plan), resident_refusal (None: a one-token-a-row step, what resident planning replays, is never split) and so max_repeats (any); it keeps can_capture True and force_double_buffer False (a leased step, the only kind a pre-plan stages, never stripes: an eager node’s floors sit above its buckets, SeqShardSpec.eager).

scatter(label, *xs, dim=None, walk=None)[source]#

This rank’s share of each of xs (whole on every rank) along dim (the spec’s axis by default), when this step splits label (SeqRange.local), contiguous; the inputs unchanged otherwise. One tensor in, one out; several in, a tuple out. None passes through.

Contiguous because eager pointwise ops keep their first input’s layout: a view of a channel-major stream (Wan2.2’s patchified latents) would carry that layout through every block’s norms and residual adds.

walk, the step’s walk where the caller’s frame is compiled per walk: a walk the shard never splits (outside walks) traces straight through, as at one SP rank, rather than breaking the frame.
