# Rulings M* has already made

Calls maintainers have made on how a feature should be shaped, each with where it was made. A design or PR that goes against one needs new evidence that answers the reason given (hard rule R2 in `../SKILL.md`). Each Status is one of four:

- **main**: on main today, in the code or in `AGENTS.md`.
- **decided**: settled by a maintainer in a review, an RFC, the review standard or a decision log, and not on main yet.
- **design**: a maintainer's proposed design, with its PRs in progress. It is the current direction, not a given.
- **trial**: a review rule still being tried out. Treat it as a question to ask, not a rule to enforce.

Sources: `AGENTS.md` on main, Gaurav Shah's review standard (`../SKILL.md`), the review threads named in each entry, and the preemption design drafts. The architecture map (`architecture/` beside this file) has the code behind each mechanism of main named here, as of Oct 25 2026: check a ruling marked main in the base tree before citing it.

## Where a feature lives

1. **Models declare, the engine executes.** Capture, resource state, streams and synchronization belong to the engine, batch selection to the micro-scheduler, and a model declares what it needs. Model code that reimplements an engine mechanism is a defect even when it works, since it opts out of batching, capture, eviction, offload and backpressure. `AGENTS.md` keeps two caveats: a cross-layer feature that would block a model can land per model first, with the system work noted and assigned, and lightweight model state such as Qwen3-Omni's fixed-size code-predictor cache can stay in the model. *Status:* main (`AGENTS.md` invariant 1).
2. **A behavior only some models need is a helper they opt into.** The engine doesn't apply it to every model. Only the last chunk of a prompt samples a real token, so `keep_final_chunk_samples` wraps a submodule's `SamplerStep` and each submodule that needs it calls it in `declare_step`, rather than the engine filtering sampler rows for all models. *Status:* main as `AGENTS.md` text (invariant 1). The helper itself is in #365, which is open and expected to merge soon.
3. **A cross-cutting feature lives below the models, not in a hook each one implements.** #365 put chunk state in six layers and asked each of four models for four to six hooks, two of them the same final-chunk bookkeeping. The review of #365 asked whether chunked prefill should be a loop on the LLM node instead, which main already speculates like decode, and the review backed the question. *Status:* decided, Oct 25 2026 (review standard R13, #365 round two).
4. **One hook that returns a policy object, not several parallel hooks.** Chunked prefill's four submodule methods became one `get_chunking_policy(graph_walk)`, a frozen dataclass the engine caches per (node, walk). *Status:* main as `AGENTS.md` text, under "Design patterns that have worked", which says not to cite it as a rule, so it is a suggestion. The code is in #365.
5. **A structural restriction known at startup is enforced at startup.** #365 passes the chunkable (node, walk) pairs to the graph runtime's constructor as `disable_spec_node_walks`, so the runtime can never return them, instead of the worker filtering speculation targets each step. *Status:* main as `AGENTS.md` text, under "Design patterns that have worked", which says not to cite it as a rule, so it is a suggestion. The code is in #365.
6. **Sliding-window attention: the complete version is a window that a group of layers declares on the paged KV cache.** #379's window attention was split into #855, which is on main and windows attention only, with every KV page still kept. The complete version is open for #379's author or a maintainer to take. *Status:* decided, Oct 23 2026 (review decision). #855 is main.
7. **Per-deployment numbers go in the serving config.** Sizing goes under `resources:` in the YAML. A tuning value a deployment may change, such as a per-step token budget, is serving config, not an environment variable added for testing or a Python constant. *Status:* main (`AGENTS.md` invariants 2 and 9).
8. **A performance path that measures neutral is deleted, not left behind a switch.** On the Qwen3.5 PR a stream manager and a fused-norm flag measured neutral and were removed, and segment-count graph buckets were reverted. *Status:* main (`AGENTS.md` invariant 9).
9. **Hardware is config.** `node_groups` map nodes to ranks, and code asks `current_platform` about the vendor. No model code branches on rank counts or device indices. *Status:* main (`AGENTS.md` invariant 8).
10. **Park an example built for one framework, and ask for the fix every client gets.** #476's LiveKit agent example was parked: the agent logic runs in LiveKit, M* refuses tool calls, and an example already points LiveKit's OpenAI TTS plugin at M*. The `/v1/audio/speech` `stream_format` streaming and the disconnect release were asked for as their own PR, since they help every OpenAI SDK client. *Status:* decided, Oct 24 2026 (review decision).

## Lockstep decisions

11. **Rank 0 decides and the followers replay, through the step's own broadcast.** A decision a follower needs rides as a typed field on `ScheduleTPNode`, as `resident_delta`, `prefix_hits` and `page_trails` do. #754's wait for each follower to report its inputs before rank 0 schedules was a second mechanism beside that, so it was sent back. A separate message would need its order against the step inferred, as #792 had to for removals, which carry the step they follow for that reason. *Status:* decided, Oct 25 2026 (review decision). #754 is closed. The broadcast and #792's stamped removals are main (`AGENTS.md` invariant 11).
12. **A replicated value is derived from what the system already decides, not kept by hand.** A fix that had each node declare its shape-setting inputs, about 25 across 7 families, was refused: "when you ask for tuning or hand counts, that's most likely a patch". A hand-kept list a new model can get wrong fails like a tuned constant. *Status:* decided, Oct 25 2026 (review decision).
13. **A rare failure is handled on its own path, not with a gate every request waits on.** #754's read gate made every TP request wait for each follower's report before its first step, to cover a read that almost never fails. The review asked for the fix on the failure path instead, and #419 does it: only the request whose read failed fails, and only steps that take an input the followers read pay the check. *Status:* decided, Oct 24 2026 (review decision). #419 is approved, and the approval was kept at its current head on Oct 25.
14. **A row leaves a lockstep step on every rank, before `prepare_inputs`.** Qwen3.5's `prefill_vision` runs a vocab-parallel embedding, an all-reduce per text part, inside `prepare_inputs`, so a rank that prepares a row the others don't runs collectives with no partner. That is why a follower can't stand in its own row for one it couldn't read, which is what an Oct 25 suggestion on #419 (build the row from the walk's capture input) would have done. *Status:* decided. The author found it on #419 on Oct 25 and moved the check before `prepare_inputs`, and the approval was kept at that head (review decision, Oct 25 2026).
15. **A lease holds on every rank or isn't counted, and a rank that can't follow exits rather than asserting alone.** Both came from #400's TP points, folded into the slim admission PR, and the preemption design keeps them: a follower whose counts can't take rank 0's move exits. *Status:* decided, Oct 24 2026 (review decision), and design.
16. **Replicated state moves only before a step's broadcast or after its admit.** The main thread runs ahead of the GPU thread, so a mutation landing between the two lets a rank admit the step from a different state than its peers. *Status:* main (`AGENTS.md` invariant 11).
17. **Under speculation, rank 0 makes a lockstep decision only where main already moves pages.** That is a scheduling pass after the admit fence, or after a refused step, from which main builds no speculative step, so a speculative step never carries a move made after it was sent. *Status:* design (preemption design §6).

## Memory pressure, admission and preemption

On Oct 16 2026 #400's review parked its strict admission control as the way M* handles memory pressure and chose recompute preemption next, keeping admission control as a backstop. The proposed preemption design of Oct 24 2026 builds that, in PRs A1, R1, R2, R3 and R4, none of them on main yet.

18. **Over-subscription is backpressure the scheduler resolves.** A full pool refuses the admit, and the worker evicts, offloads or holds. It is never an exception inside a forward. *Status:* main (`AGENTS.md` invariant 1).
19. **A preemptible request reserves its prompt, not its worst case.** Reserving every request's worst case on #400 raised chat TTFT p50 from 0.45 s to 17.7 s behind image requests. A guaranteed request (ruling 20) also reserves its growth. *Status:* design (A1). The decision to park #400 is decided, Oct 16 2026.
20. **A request's class comes from the request itself, set once by the conductor.** A request is guaranteed (reserves its whole footprint, never preempted) when it streams audio out, when its KV comes from media or another node's outputs, and in a node's pools when that node keeps no token ids for it. Otherwise it is preemptible. A priority or a per-request flag would be one more input to tune, when the footprint and the output already decide, and the v2 RFC adds that no config option or request field overrides the class. The conductor sets it because it alone sees every resource's layout: a class each worker set from its own pools would let the Thinker's worker drop a request whose Talker is speaking. *Status:* design §1.
21. **Order among requests is one number from the conductor.** Queues and victim choice go by an arrival number the conductor assigns from one counter. Numbers set by each worker can differ, since requests reach workers on separate sockets, and two workers could each drop a different request so that neither makes progress. *Status:* design §3.1.
22. **Drop victims are the newest preemptible requests.** Not the least recently active, which can be the oldest request so that nothing guarantees progress, and not the largest, which would be dropped every time it grows. Only the head of a queue is admitted, so nothing newer passes the oldest request. When the host pool has room, the worker still offloads the least recently active request first, as main does (ruling 26). *Status:* design §2, §3 and §3.2.
23. **No timer decides when a request runs again.** A request that can only wait watches the room its failed grant saw, and a dropped request returns when its whole history plus a page fits. These replace main's 50 ms hold for KV pages. #461 stays a draft until the preemption work decides when an offloaded request returns, by pages rather than step time. *Status:* design §3.2 and §5.2, and decided for #461 on Oct 24 2026 (review decision).
24. **The reservation rule lives where every grant passes.** `KVManager._alloc` checks every grant against the reservations under the lock it already holds, since a check anywhere else lets a growing request take a page another request reserved. *Status:* design §2.
25. **Lost KV is rebuilt by a row in the engine's batch that the graph runtime never sees.** The request stays in its decode walk, and the row runs under the node's prefill walk, in a step of its own. Switching the request's walk for one step would touch both runtimes, the output edges, the walk's completion message and the loop-back. Running the prefill schedule again through the conductor would need a stop outside the running step, kept prompt tensors, a resume hook in each model and a way to continue the sampler. Removing and re-ingesting the request would lose the sampler's RNG offset and repetition mask. This keeps something out of the graph runtime on purpose, which the disguise check otherwise flags, so a design that copies it states the same reasons. *Status:* design §5.3, with the conductor reason from the v2 RFC §5.3.
26. **When the host pool has room, offload before dropping.** Dropping and rebuilding made 32 Bagel requests that share a prefix take about 4x as long with 256 host pages. A drop needs no host pool, so preemption still works without one, which is the default. The v2 RFC had dropped every victim. *Status:* design §3 and §4.
27. **For voice, a gap mid-stream is worse than a late start.** A request that streams audio is never preempted, and the TTFA p99 cost of queueing guaranteed requests is accepted. *Status:* design §1 and §8, and the standing view that no gap once a stream starts outranks first-audio latency (decided).

## Structural, not tuned

28. **Correctness, liveness and scheduling rest on structural signals.** A step count, the pool's state, a reservation, message order or an explicit marker, not a wall-clock window, a timeout, a retry count or a hand-tuned constant. #461's one-second windows became a count of steps, and #552's 64 tries of 1 ms became a wait on the lock. A model default for a quality trade-off states the rule that picks it. *Status:* decided (review standard R4).
29. **One mechanism per concern.** A change extends the mechanism main already has. #465's resend queue beside the drain record's TTL, #729's `unadmittable_buckets` beside `_blocked_buckets`, #459's two dicts beside `StreamingConnectionState` and #552's per-segment lock beside the namespace lock were each sent back. Two open PRs that count the same thing on one frame fold into one count (#459 and #551). *Status:* decided (review standard R3).
30. **A PR whose approach doesn't fit main's mechanisms is closed and redone.** It is not patched toward a fit, and not merged with a fallback. *Status:* decided, Oct 25 2026 (review standard, Stance).
31. **Fix the cause.** No broad except over half-updated state, no leak bounded by a budget, no retry for a failure the system never produces, no exemption from a check. *Status:* decided (review standard R5).

## Host cost and the async worker

32. **Per-step host work stays off the scheduling path, and nothing scans every live request on every step.** Data crossing the Python and Rust boundary goes columnar, bulk data travels as a tensor edge, and a backlogged row's derived facts are computed once and carried on the batch. *Status:* main (`AGENTS.md` invariant 6). Stating the cost against batch size, requests in flight and nodes is trial.
33. **The only free host read is `check_stop`.** Any other host sync in the step path collapses the async pipeline. Moving GIL-holding work to another thread adds contention, so a host-bound step is fixed by deleting work. *Status:* main (`AGENTS.md` invariant 7).
34. **Python and Rust runtimes behave the same.** A behavior change to the graph runtime, the wire format or edge semantics lands on both sides or is explicitly gated. *Status:* main (`AGENTS.md` invariant 5), and decided (review standard R8).

## State and lifecycle

35. **Handle-keyed state is purged on every release path and listed in `rid_table.py`.** Clearing at the top of a per-step routine is not a substitute, since early returns skip it. *Status:* main (`AGENTS.md` invariant 14), and decided (review standard R9).
36. **Every new piece of state has an owner, a thread and an end on every exit path.** Cancel, failure, OOM, removal mid-step and a TP rank going away. #365's `prepared` was written by the GPU thread and cleared by the main thread, and #371's dropped chunk was an exit path nobody walked. *Status:* trial (review standard R15).

## Proving a feature

37. **Every pair in the feature matrix is supported and tested, or refused at config load.** TP, SP, prefix cache, CPU offload, accelerator graphs, speculation, streaming and a null or opt-out config. Most of the chunked prefill stack's bugs sat in one cell each. *Status:* trial (review standard R14).
38. **A default-on core feature has one switch that restores main's path, and a run shows it.** On #365, the null config still measured every row and barred speculation, and the chunking-off arm is what showed the ITL cost was chunking's. *Status:* trial (review standard R16).
39. **A model hook's contract is checked by the engine at load.** A wrong or missing implementation fails loudly then, not as a wrong answer later. *Status:* trial (review standard premise checks).
40. **A performance claim is measured at the head, on stock configs, against main.** On the workload it claims, on one it should leave alone, and at p99, with host time beside device time. A gain on one model counts once the other models on the path are measured too. Boot stays within 5% of main. *Status:* main (`AGENTS.md` invariant 10), and decided (review standard R7 and premise checks).
41. **A stress config no deployment runs is not evidence for or against a PR.** A 48-page KV pool result was dropped from a #365 draft as unrealistic. *Status:* decided, Oct 24 2026 (review decision).

## Backends, devices and config (from the reviews of #262, #341, #360, #379 and #386)

42. **A new backend implements the existing interface and registers in its factory.** The review of #386 asked for an abstract `AllReduce` with SymmMem and NCCL subclasses, and asked #379 to make its fused all-reduce implement the `AllReduce` interface and join `AllReduce.new` rather than add a path beside it. *Status:* main (`mstar/distributed/all_reduce.py:44`), from #386 (Oct 16 2026) and #379 (Oct 24 2026).
43. **A per-component choice is config, per node or per (node, walk), not an environment variable that acts globally.** `MSTAR_GRAPH_COMPILE_MODE` and `MSTAR_MLA_DECODE_BACKEND` were asked to become config, with `flashinfer_backend` in `AttentionSpec` as the model. EP's settings went on the node group (`ep_config`) instead of inside Qwen3-Omni, with a shared `instantiate_moe_block`. *Status:* decided on #386 (Oct 16 2026). `ep_config` is main (`mstar/model/components/moe_parallel.py`, from #360).
44. **Capture capability and accelerator-specific branches go behind one interface, not `device.type` checks in model code.** The review of #262 asked for a narrow `DeviceCapability` and a `Resource.can_capture()` that the runner reads, so model code stays agnostic to the accelerator. Checking `device.type == "cuda"` to ask whether a device is a GPU is still fine, and vendor checks go through `current_platform` (ruling 9). *Status:* main (`mstar/utils/device.py:14`, `mstar/engine/resources/base.py:114`).
45. **An option a backend can't honor is refused, not silently ignored.** `context_only=True` was ignored by non-MLA attention backends, so a step that declared it would attend over the appended tokens too. The review of #386 asked for the key to be refused on the other backends. *Status:* main (`refuse_context_only`, `mstar/engine/resources/attn/config.py:142`), from #386.
46. **A per-rank fact must not pick a collective's path.** A data pointer's alignment is a per-rank fact, and a kernel chosen by it could hang the group if one rank differs. The review of #386 raised it as probably a non-issue, and main's multimem all-reduce now chooses by message size, which every rank shares, and handles a misaligned output with a copy. *Status:* main (`mstar/distributed/all_reduce.py:210-214`).
47. **The engine passes a fact to the model explicitly, rather than the model inferring it from a convention.** On #360, a model read `per_request_states is None` to mean a synthetic step and relied on padding rows having length zero. The review asked for a boolean and a `real_seq_len` instead. *Status:* main (`synthetic` and `real_seq_len`, `mstar/model/submodule_base.py:467-471`).
48. **A default stays as good as before on the stock configs.** #262 turned BAGEL's accelerator graphs off by default, so every default CUDA config would have run eager. The default stays on, and the XPU configs that need it turn it off. *Status:* main (`configs/bagel_xpu_tp2.yaml:3`), from #262.

## Failing loudly, and what stays out of the code

49. **An unsupported feature fails with one clear 400 on every route, never with a silently wrong answer.** Tool messages and a `tools` list get "tool calling is not supported for this model" until tool support lands as one joint feature, on the default and Rust frontends and the Dynamo bridge alike. *Status:* main (#340, `mstar/api_server/openai/adapters.py:194`).
50. **Future work lives in the PR description, never as hooks, flags or parameters in code.** *Status:* decided (design notes, Oct 10 2026).
51. **A hand-tuned value, a copied constant or an estimate that holds only for today's models is named in the PR description, with a question for reviewers.** *Status:* decided (design notes and the code bar).
52. **Running streams come first, and a scheduling policy is simulated on measured step costs before any GPU run.** #348 tried to make first audio faster at capacity, and every design moved the wait rather than removing it, adding stalls to running streams or losing throughput. It was closed, keeping main's behavior. The lessons recorded: fix the priority order before designing. *Status:* decided, Oct 10 2026 (design log).
53. **What to capture is decided in a planning pass before capture, the same on every boot and every rank.** The review of #341 pointed out that capturing in submodule order until memory runs out is non-deterministic across boots and can capture one node's graphs and none of another's, and asked for a planning pass that decides what to capture before any capture runs. Every decision that changes which graphs a rank captures is agreed across ranks. *Status:* main (#341, `plan_captures` at `mstar/engine/accelerator_graph_runner.py:503`).
54. **A compiled encoder must not recompile after boot.** Each compile rounds differently, so cached KV stops matching. Its varying dims are marked dynamic at the first compile, in code, not with a warm-up per config. *Status:* decided (design notes, Oct 9 2026, for the prefix cache digests).
55. **Nothing beyond what is needed.** Every added line changes behavior or explains a hazard, and a change deletes what it replaces. No guard for a case no caller reaches (#561's `if covered:`, #546's `align_up` overflow), and a guard that stays names the caller that reaches it. *Status:* decided (review standard R12, code bar).
