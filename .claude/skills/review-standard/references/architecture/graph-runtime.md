# Graph runtime and streaming mechanisms on main

Checkout: main at `fa381afd6`. Paths are relative to the repo root. "Invariant N" means item N of the "Invariants" section of `AGENTS.md`.

The worker touches graph state only through the `GraphRuntime` contract (`mstar/graph/runtime/base.py:517`). `PythonGraphRuntime` (`mstar/graph/runtime/python.py:117`) is the reference implementation, and the Rust `GraphRuntime` (`rust/src/graph/runtime.rs:139`) sits behind `RustGraphRuntime` (`mstar/graph/runtime/rust.py:208`). `resolve_graph_runtime_type` (`mstar/graph/runtime/utils.py:13`) picks one per process, so every behaviour change below lands on both sides or is gated (Invariant 5). Parity tests are `test/rust/test_runtime_parity.py`, `test/rust/test_rust_graph_runtime.py` and `test/modular/test_graph_runtime.py`.

### Graph sections and I/O derivation
- **Does:** `GraphNode`, `Sequential`, `Parallel` and `Loop` compose a walk's graph, and `get_inputs_outputs` derives each section's external inputs, external outputs and loop-back pairs from `(edge name, next_node)` pairs.
- **Where:** `mstar/graph/base.py:127` (`GraphSection`), `:230` (`GraphNode`), `:385` and `:400` (`Sequential`), `:439` and `:454` (`Parallel`), `:480` and `:523` (`Loop`), `:687` (`top_level_entities`). Rust has no section tree. It receives the derived sets through `worker_graph_args` (`mstar/graph/runtime/rust.py:104`) into `compile_one` (`rust/src/graph/compile.rs:49`), which stores them as `LoopSpec.loop_back` and `external_inputs` (`rust/src/graph/spec.rs:123`).
- **Keeps:** A loop's `_external_inputs` and `_loop_back_inputs` are computed once at construction (`mstar/graph/base.py:630`) and handed to Rust verbatim (`mstar/graph/runtime/rust.py:143`), so both runtimes agree on what a loop re-injects each iteration and what it filters when it finishes.
- **Used by:** `Loop.__post_init__` (`mstar/graph/base.py:625`), the per-worker loop rebuild in `_divide_into_worker_graphs` (`mstar/model/base.py:363`), registries built over `top_level_entities` (`mstar/graph/base.py:708`), the stream-walk startup check (`mstar/model/base.py:594`).
- **Extend via:** A new section kind is a `GraphSection` subclass plus matching branches in `top_level_entities` (`mstar/graph/base.py:697` asserts only `Sequential` or `Parallel`), `_divide_into_worker_graphs` (`mstar/model/base.py:254`) and the compile seam. The tempting duplicate is re-deriving loop-back or external sets in Rust or in the worker, which `mstar/graph/runtime/rust.py:107` rules out so the two cannot drift.
- **Breaks if:** A node's output reuses one of its own input names, since loop-back is detected by `next_node == self.name` (`mstar/graph/base.py:318`). A loop that is stopped dynamically keeps its default uuid name (`mstar/graph/base.py:485`), because stops are matched by loop name.

### Walks and worker graphs
- **Does:** Each walk from `get_graph_walk_graphs` is split by `node_groups` into `WorkerGraph`s, merging adjacent sections on the same group, and each worker keeps a per-request instance of every local worker graph.
- **Where:** `mstar/model/base.py:177` (`WorkerGraph`), `:254` (`_divide_into_worker_graphs`), `:456` (`_get_worker_graphs_for_graph_walk`), `:499` (`get_worker_graphs`), `:817` (`get_graph_walk_graphs`). Python per-request state is `WorkerGraphQueues` (`mstar/worker/node_manager_utils.py:57`, pickled template at `:74`, `add_request` at `:105`) wrapping `WorkerGraphIO` (`mstar/graph/graph_io.py:23`). Rust compiles one `CompiledGraph` per worker graph, shared by `Arc` (`rust/src/graph/spec.rs:133`), and builds a `RequestState` per request (`rust/src/graph/state.rs:195`) in `add_request` (`rust/src/graph/runtime.rs:1616`).
- **Keeps:** A `(walk, node)` resolves to one local worker graph (`mstar/graph/runtime/python.py:192`, `rust/src/graph/runtime.rs:161`), and each node of a walk sits in exactly one node group (`mstar/model/base.py:517`). `add_request` opens every local worker graph of the partition, but only the current walk's graphs are live for routing, and `set_walk` re-derives that list (`mstar/graph/runtime/python.py:320`, `rust/src/graph/request.rs:217`).
- **Used by:** `_make_graph_runtime` (`mstar/worker/worker.py:125`), `set_walk` on every conductor-driven pass (`worker.py:1180`), `get_worker_graph_id_for_node` in the scheduler (`mstar/worker/micro_scheduler.py:702`), the conductor's per-worker-graph maps (`mstar/conductor/conductor.py:690`).
- **Extend via:** Placement goes through `node_groups` and `_divide_into_worker_graphs` (Invariant 8). A graph shape the runtime cannot serve is refused in the startup checks `_check_walk_placement`, `_check_stream_driven_walks` and `_check_loop_successors` (`mstar/model/base.py:517`, `:564`, `:618`). The tempting duplicate is a per-request runtime guard or a second node-to-worker-graph index.
- **Breaks if:** A stream-consuming section is merged with its neighbour. `_divide_into_worker_graphs` never merges one (`mstar/model/base.py:302`, `:324`), because done detection counts top-level entities per worker graph.

- **Where:** Declared by `Model.get_combined_graph_walks` and validated by `combined_walk_of` (`mstar/model/base.py:747`, `:751`). Python matching is `_combined_walk_of` and `_names_walk` (`mstar/graph/runtime/python.py:139`, `:592`), Rust is `combined_walk_of` and `names_walk` (`rust/src/graph/runtime.rs:177`, `:465`). The multi-walk API is `RequestWalks` (`mstar/graph/runtime/base.py:367`), `pop_walk_rids` (`:755`, `mstar/graph/runtime/python.py:542`, `rust/src/graph/runtime.rs:2197`) and `RouteInput.walks` with `rid_walk_idx` (`mstar/graph/runtime/base.py:458`).
- **Keeps:** A combined name is only ever a scan target or exclusion. Ready nodes are reported under real walks, and every row completes and routes in its own walk (`mstar/graph/runtime/python.py:1362`, `rust/src/graph/runtime.rs:2490`). Startup refuses a combined walk that splits by capture key or spans TP groups (`mstar/worker/engine_manager.py:79`, `:99`).
- **Used by:** The scheduler's key map, `_key` and `label_for` (`mstar/worker/micro_scheduler.py:226`, `:717`, `:721`), its multi-walk pop (`:1117`), the route input (`mstar/worker/worker.py:3609`), resource splits keyed by combined walk (`mstar/engine/resources/spec.py:27`, `mstar/engine/resources/attn/flashinfer.py:42`, `mstar/engine/resources/linear_attn/gdn.py:59`).
- **Extend via:** Declare the grouping in `get_combined_graph_walks` and carry per-row walks through `RequestWalks`, `PopRidsOutput.rid_walk_idx` and `RouteInput.walks`. The tempting duplicate is calling `set_walk` with the combined name, or a separate per-walk batch path in the worker.
- **Breaks if:** A new runtime call keyed on `(node, walk)` assumes one walk per batch. Without `walks`, `complete_and_route_batch` routes every row in `graph_walk` (`mstar/graph/runtime/base.py:456`).
- **See also:** `worker-scheduling.md` › Combined walks.

### Input slots and ready sets
- **Does:** Each node keeps three input slots (current, next iteration, speculative), and each per-request worker graph keeps the set of nodes whose current inputs are complete and the set whose only missing inputs are streamed.
- **Where:** `ReadySignals` (`mstar/graph/base.py:146`, `update` `:173`, `clear` `:191`, `remove` `:207`), `GraphNode.ingest_input` (`:293`), `WorkerGraphStateRegistry.register_ingested_input` and `reseed_streaming_ready` (`:805`, `:843`). Rust `Slot` and `NodeState` (`rust/src/graph/state.rs:29`, `:72`), `RequestState::ingest` (`:317`), `refresh_ready` (`:245`), `note_ingested_for_streaming` (`:276`), `reseed_streaming_ready` (`:298`). The entry point is `ingest_inputs_batch` (`mstar/graph/runtime/base.py:708`, `mstar/graph/runtime/python.py:488`, `rust/src/graph/runtime.rs:1934`).
- **Keeps:** An edge fills the current slot, else the next-iteration slot when `can_buffer` is set, else it is refused and the caller offers it to the next worker graph or hands the chunk back to its `StreamBuffer` (`mstar/graph/base.py:303`, `rust/src/graph/state.rs:324`). A node whose inputs are all streamed is seeded into the streaming-ready set and reseeded each time its slot is cleared (`mstar/graph/base.py:797`, `rust/src/graph/state.rs:215`).
- **Used by:** `_add_new_request` (`mstar/worker/worker.py:886`), signal-only edges in `_process_new_inputs` (`worker.py:1219`), `_check_ready_tensors` (`worker.py:1459`), `_poll_stream_buffers` (`worker.py:1445`), local routing (`mstar/graph/runtime/python.py:1071`, `rust/src/graph/runtime.rs:2740`).
- **Extend via:** A new readiness condition is a field or mask on the slot plus a branch in `register_ingested_input` and `refresh_ready`, on both sides. The tempting duplicate is a worker-side readiness dict or a second readiness check in the scheduler.
- **Breaks if:** A streamed chunk is ingested with `can_buffer=True`, which parks it in a next-iteration slot that may never run (`mstar/graph/base.py:308`, `mstar/worker/worker.py:1447`). `WorkerGraphStateRegistry.reset_for_iter` and its next-iteration sets (`mstar/graph/base.py:851`) are unreachable, because only a loop's inner registry is reset per iteration (`mstar/graph/base.py:530`, `:678`) and Rust does not port them (`rust/src/graph/state.rs:7`), so a change that relies on them does nothing.

### Loops
- **Does:** A `Loop` runs its section up to `max_iters`, re-injects its external inputs each iteration, caches its declared and accumulated outputs, and finishes early once its finish signal is set.
- **Where:** `Loop` (`mstar/graph/base.py:480`, `register_finished` `:515`, `ingest_external_input` `:533`, `complete_iter` `:549`, `maybe_cache_output` `:597`) and `LoopStateRegistry` (`:740`). Rust `LoopSpec` (`rust/src/graph/spec.rs:107`), `LoopState` (`rust/src/graph/state.rs:97`), `entity_completed` (`:553`), `cache_outputs` (`:584`), `finish_loop` (`:613`), `advance_loop` (`:660`), and the structural `held_mask` (`rust/src/graph/compile.rs:160`). Per-request caps come from `Model.get_loop_caps` (`mstar/model/base.py:970`) and are applied at `mstar/worker/node_manager_utils.py:111` and `rust/src/graph/runtime.rs:1704`.
- **Keeps:** A loop ends when all its directly managed entities have completed and either `curr_iter + 1 == max_iters` or the finish signal is set, and on finish its loop-back pairs are filtered from routing (`mstar/graph/base.py:558`, `rust/src/graph/state.rs:569`, `:620`). Re-injected external inputs are held (`_persist_for_loop` in Python, `held_mask` in Rust) so slot clears do not dereference them, and a streamed input is never re-injected (`mstar/graph/base.py:537`, `rust/src/graph/state.rs:344`).
- **Used by:** `WorkerGraphIO.mark_node_complete` (`mstar/graph/graph_io.py:89`), the Python completion (`mstar/graph/runtime/python.py:1361`), `RequestState::complete` (`rust/src/graph/state.rs:528`), the per-worker loop rebuild (`mstar/model/base.py:339`), `_can_continue_loop` (`mstar/graph/runtime/python.py:918`, `rust/src/graph/runtime.rs:746`).
- **Extend via:** Per-iteration results a downstream node needs go through `Loop.accumulated_outputs`, and `_check_loop_successors` (`mstar/model/base.py:618`) refuses the alternative. Per-request iteration bounds go through `get_loop_caps`. Early exit goes through the loop-stop mechanism below. The tempting duplicate is a model-side iteration counter or a node that drops its own loop-back edge.
- **Breaks if:** One streamed chunk has to feed N iterations, which the split cannot express. The TODO at `mstar/model/base.py:347` says `_divide_into_worker_graphs`, `Loop._is_streamed_input` and the Rust `held_mask` have to change together. The comment at `rust/src/graph/state.rs:647` still describes two divergences from Python's nested-loop cascade, but `Loop.complete_iter` now populates outputs before cascading and keeps the parent's result (`mstar/graph/base.py:569`), so that comment is stale.

### Loop stops
- **Does:** Turns `check_stop`'s loop names into finish signals on every local worker graph that carries the loop, records each stop as pending for one postprocess, sends `STOP_LOOPS` to peer workers, and applies a peer's stop only when its observation is newer.
- **Where:** `stop_loops_batched` (`mstar/graph/runtime/base.py:879`, `mstar/graph/runtime/python.py:1192`, `rust/src/graph/runtime.rs:3042`), `apply_peer_loop_stops` (`mstar/graph/runtime/base.py:898`, `mstar/graph/runtime/python.py:1274`, `rust/src/graph/runtime.rs:3119`), the pending-stop API (`mstar/graph/runtime/base.py:34`, `:911`, `:917`, `:924`), and stop ordering by `NestedLoopIndices.label_context_gt` (`mstar/graph/loop_indices.py:16`) and `LoopStopTime::later_than` (`rust/src/graph/request.rs:51`).
- **Keeps:** A stop only sets the finish signal and never moves `curr_iter`, so the loop context snapshot taken in `complete_and_route_batch` is unaffected (`rust/src/graph/runtime.rs:2532`). Pending stops last one postprocess and are purged on `remove_request` because handles recycle (`mstar/worker/worker.py:3284`, `mstar/graph/runtime/python.py:302`, Invariant 14), and a peer's stop is applied without fanning out again (`mstar/graph/runtime/python.py:1288`).
- **Used by:** Postprocess (`mstar/worker/worker.py:3393`), dropping rows that overstayed a stop (`worker.py:3255`), stream-terminated loops (`worker.py:3348`), peer `STOP_LOOPS` (`worker.py:1232`), the speculation loop filter (`mstar/graph/runtime/python.py:925`).
- **Extend via:** A new stop source adds loop names to the per-rid `stops` dict before `stop_loops_batched`, as the stream-terminated loop does at `mstar/worker/worker.py:3348`. The tempting duplicate is setting `_finish_signal` directly or sending a separate stop message.
- **Breaks if:** Drift found in the code: Python records a peer's stop time only when it is newer (`mstar/graph/runtime/python.py:1283`), while Rust records it unconditionally (`rust/src/graph/runtime.rs:3152`), and `test/rust/test_rust_graph_runtime.py:873` asserts the Rust behaviour. What this does to a stop re-delivered after an older one is a hypothesis I did not run. A stop for a loop the current walk lacks is logged and dropped rather than raised (`mstar/graph/runtime/python.py:369`).

### Completion and done reporting
- **Does:** Marks a node complete, counts top-level entity completions per worker graph, resets every worker graph of the walk that is now done, and reports those in `WORKER_GRAPHS_DONE` with the persist signals, token counts, emitted chunk names and stream item counts buffered since the last report.
- **Where:** `GraphStateRegistry.mark_entity_complete` (`mstar/graph/base.py:714`), `WorkerGraphStateRegistry.mark_entity_complete` (`:828`), `RequestState::complete` and `root_entity_done` (`rust/src/graph/state.rs:488`, `:543`). The done sweep is at `mstar/graph/runtime/python.py:1085` and `rust/src/graph/runtime.rs:2643`. The buffers are `GraphRuntimeRequestInfo` (`mstar/graph/runtime/python.py:95`) and `PendingOutputs` (`rust/src/graph/request.rs:103`). The frame is built at `mstar/graph/runtime/python.py:1584` and `rust/src/graph/runtime.rs:323`.
- **Keeps:** A worker graph is done when every top-level entity has completed once, with a loop counting as one entity, and the sweep covers every graph of the request in the walk because a graph can finish without ingesting anything (`mstar/graph/base.py:687`, `mstar/graph/runtime/python.py:1085`). Persist signals ride the next report so they cannot race it, and `partition_done` is withheld while the node is in flight speculatively (`mstar/graph/runtime/python.py:1555`, `rust/src/graph/runtime.rs:335`).
- **Used by:** `complete_and_route_batch` and `send_outputs` (`mstar/graph/runtime/base.py:929`, `:950`), called from `mstar/worker/worker.py:3595` and `:3719`, and read by the conductor at `mstar/conductor/conductor.py:1745`.
- **Extend via:** A new per-request fact the conductor needs at pass end goes into the pending buffer and the `WORKER_GRAPHS_DONE` frame on both runtimes. `rust/src/graph/request.rs:94` gives the reason it lives on the request record and not in a handle-keyed side map. The tempting duplicate is a new worker-to-conductor message.
- **Breaks if:** The graph shape lets a worker graph count done early, for example a self-triggered stream consumer beside another top-level entity, or a loop member feeding a node outside the loop in the same worker graph. Both are refused at startup (`mstar/model/base.py:564`, `:618`). A done graph that is not reset latches `is_done` and never becomes ready again (`rust/src/graph/runtime.rs:2649`).

### Ready scan, pop and push back
- **Does:** Reports the `(node, walk, rids)` whose graph inputs are satisfied, pops a chosen set out of the ready set, and puts a popped set back when its batch cannot run.
- **Where:** `has_ready_excluding`, `get_ready_nodes`, `pop_rids`, `pop_walk_rids` and `push_back_node` (`mstar/graph/runtime/base.py:764`, `:778`, `:737`, `:755`, `:794`). - **Keeps:** These answer graph readiness only, and engine readiness stays with the caller because it can fail a request (`mstar/graph/runtime/python.py:605`). A pop clears only ready-set membership, the inputs stay in the current slot until `cleanup_consumed_inputs` in postprocess (`mstar/worker/worker.py:3246`), and `push_back_node` restores membership unconditionally without recomputing readiness (`rust/src/graph/state.rs:410`).

- **Breaks if:** `push_back_node` runs after `cleanup_consumed_inputs` for the same rids, which leaves a ready node with empty slots, and the next pop reads its inputs from those slots (`mstar/graph/runtime/python.py:575`, `rust/src/graph/runtime.rs:2282`). The rationale at `rust/src/graph/state.rs:412` says cleanup normally runs before the push back, which does not match the admit-refusal path I traced, where no forward and so no postprocess has run. UNVERIFIED which order holds at every call site.
- **See also:** `worker-scheduling.md` › Ready scan and engine readiness, `engine-resources.md` › Readiness, retrieve and publish.

### Speculation targets and staged prep
- **Does:** From a running node's structural outputs, finds the nodes that will be ready next, then per rid ingests buffered stream chunks, checks readiness against the current, next-iteration, held and speculative slots, gathers inputs, and parks what it ingested under a `spec_id` that `commit_speculation` settles.
- **Where:** `WorkerGraphIO.ingest_for_speculation` (`mstar/graph/graph_io.py:109`), `GraphNode.is_ready_for_speculation` (`mstar/graph/base.py:339`). The API is `speculate_node`, `prep_spec_rids`, `get_spec_target`, `prep_follow_spec_rids` and `commit_speculation` (`mstar/graph/runtime/base.py:803`, `:817`, `:829`, `:843`, `:857`). Python `_speculate_walk` (`mstar/graph/runtime/python.py:683`), `_stage_spec` (`:886`), `_undo_spec_ingest` (`:935`), `_prep_one_spec_rid` (`:951`). Rust `AsyncEnabledChecker::can_speculate` (`rust/src/graph/runtime.rs:123`), `speculate_walk` (`:568`), `prep_spec` (`:623`), `stage_spec` (`:731`), `prep_one` (`:772`), `RequestState::ingest_for_speculation` and `ready_for_speculation` (`rust/src/graph/state.rs:788`, `:825`).
- **Keeps:** Eligibility is structural and lives in the runtime. Source and target both need `enable_async_scheduling`, and a parallel target qualifies only under TP async, from the leader, as a same-node loop-back (`mstar/graph/runtime/python.py:691`, `rust/src/graph/runtime.rs:123`). Every nonzero `spec_id` is settled once, and a dropped rid's chunks are pulled back out without a dereference so the worker can return them to their `StreamBuffer` (`mstar/graph/runtime/base.py:857`, `mstar/graph/base.py:207`).
- **Used by:** `_can_speculate` (`mstar/worker/worker.py:2433`), `_choose_spec_target` (`worker.py:2670`), the prep (`worker.py:2742`), the commit (`worker.py:2622`), the TP follower path (`worker.py:2967`, `:3006`), `get_consumed_edges` (`worker.py:2581`).
- **Extend via:** A structural exclusion goes into the runtime's eligibility filter, `GraphNode.enable_async_scheduling`, or a set computed at startup and passed to the runtime constructor (AGENTS.md "Design patterns that have worked"). The `disable_spec_node_walks` hook that section cites lands with #365 (about to merge). A per-rid loop bound goes into `_can_continue_loop` or `get_loop_caps`. The tempting duplicate is filtering targets in the worker after `speculate_node`, or a second rollback path for stream chunks.
- **Breaks if:** Prep touches registry state, since `_undo_spec_ingest` relies on the held in-flight flag having left the registry untouched (`mstar/graph/runtime/python.py:935`). An ingest the rollback does not record by slot, current or next iteration, leaks a chunk (`mstar/graph/runtime/python.py:968`, `rust/src/graph/runtime.rs:808`). Follower prep is all or nothing (`mstar/graph/runtime/base.py:843`), so a per-rid skip there desynchronizes ranks (Invariant 11).
- **See also:** `worker-scheduling.md` › Speculation chain.

### Columnar edge blocks
- **Does:** Carries batches of edges across the runtime boundary as parallel columns (signal-name table, per-edge rid, tensor counts, flat uuids, final-chunk flags, optional destinations) rather than one object per edge.
- **Where:** `ColumnarEdgeSpecs` (`mstar/graph/runtime/base.py:65`, `add_edge` `:133`, `to_edges` `:146`, `to_input_tensors` `:177`, `select_rids` `:250`), `PopRidsOutput` (`:347`), `SpeculationPrepOutput` (`:399`), `RouteInput` (`:437`). Rust `EdgeColumns` and `EdgeColumnsArg` (`rust/src/graph/runtime.rs:1056`, `:1375`), read back by `_columns` (`mstar/graph/runtime/rust.py:190`).
- **Keeps:** Every edge carries its own rid, so callers keep no rid-major run-length invariant (`mstar/graph/runtime/base.py:81`). The order of `signal_names` differs between the runtimes, so parity compares `edge_tuples` (`mstar/graph/runtime/base.py:228`).
- **Used by:** `_edge_block` and `_one_rids_edges` (`mstar/worker/worker.py:1809`, `:1826`), batch builds through `to_input_tensors` (`worker.py:1611`, `:2772`, `:2805`, `:3043`).
- **Extend via:** A new per-edge fact is a new column on both `ColumnarEdgeSpecs` and `EdgeColumns`, which is the boundary shape Invariant 6 asks for. The tempting duplicate is a list of tuples or a per-edge object. `SpeculationPrepInput.streaming_edges` is still per edge, and the TODO at `mstar/graph/runtime/base.py:382` gives the reason.
- **Breaks if:** A column is added on one side only. Rust rejects mismatched lengths (`rust/src/graph/runtime.rs:1940`), and a stale extension build fails at request time (AGENTS.md "Testing").

### StreamBuffer and chunk policies
- **Does:** Per request and streaming edge on the consumer worker, holds arriving items in producer order and releases a chunk when the connection's `ChunkPolicy` says enough items are buffered, ending with one final chunk once the producer is done.
- **Where:** `StreamBuffer` (`mstar/streaming/stream_buffer.py:47`, `prime_context` `:87`, `pre_read_register` `:94`, `put` `:98`, `signal_done` `:112`, `has_chunk_ready` `:129`, `pop_chunk` `:150`, `store_uningested_edge` `:197`), `StreamChunk` and `StreamChunkInfo` (`:12`, `:32`). `ChunkPolicy` (`mstar/streaming/chunk_policy.py:5`) with `SlidingWindowChunkPolicy` (`:66`), `LeftContextChunkPolicy` (`:90`), `FixedChunkPolicy` (`:136`), `RampChunkPolicy` (`:166`) and `ScheduledLeftContextChunkPolicy` (`:227`). There is no Rust twin: the buffer holds tensors and stays in Python (`mstar/worker/node_manager_utils.py:202`, `mstar/graph/runtime/python.py:1524`).
- **Keeps:** Items come out in `pre_read_register` order, not arrival order (`mstar/streaming/stream_buffer.py:102`). A chunk is final only when the producer is done, every expected item was registered and read, and the buffer is empty, and exactly one final chunk is emitted unless the policy continues after the producer is done (`mstar/streaming/stream_buffer.py:118`, `:144`, `:177`).
- **Used by:** Creation from `Connection.chunk_policy_factory` (`mstar/worker/worker.py:856`), `_route_streaming_tensor` (`worker.py:1301`), local streams from `RouteOutput.local_streaming_by_signal` (`worker.py:3640`), `_pop_streaming_edge` (`worker.py:1315`), `_return_streaming_edge` (`worker.py:1368`), `_settle_final_streams` reading `continue_after_producer_done` (`worker.py:1679`).
- **Extend via:** A new chunking shape is a `ChunkPolicy` subclass returned by the connection's factory, and the consumer learns context and size from `StreamChunk.context_items` and `num_items` through `RequestStateManager.ingested_stream_chunks` (`mstar/worker/node_manager_utils.py:307`). The tempting duplicate is a model-side buffer, or trimming code that re-derives the policy's schedule (`mstar/streaming/chunk_policy.py:242`).
- **Breaks if:** End of stream is judged from `producer_done` alone. The done signal travels through the conductor and can arrive before the last items (`mstar/streaming/stream_buffer.py:82`), so a check that ignores `_num_items_expected` closes the stream early.

### Streaming edges and consumer triggering
- **Does:** Moves data between async partitions: the producer routes a streaming edge like any other but it bypasses the graph queues, the consumer worker buffers it, and the poll loop ingests ready chunks as synthetic edges that make the consumer node ready.
- **Where:** `StreamingGraphEdge`, `Connection` and `PartitionTopology` (`mstar/streaming/topology.py:9`, `:24`, `:33`), declared by `Model.get_partition_topology` (`mstar/model/base.py:1045`). Streamed inputs are registered on the node at split time (`mstar/model/base.py:267`, `mstar/graph/base.py:282`). Producer side is `mstar/graph/runtime/python.py:1030` and `:1141`, and `rust/src/graph/runtime.rs:2603` and `:2818`. Consumer side is `_process_new_inputs` (`mstar/worker/worker.py:1157`), `_check_ready_tensors` (`worker.py:1459`) and `_poll_stream_buffers` (`worker.py:1426`), gated at `mstar/graph/runtime/python.py:523` and `rust/src/graph/runtime.rs:450`. End of stream is `_settle_final_streams` (`mstar/worker/worker.py:1653`), `mark_stream_partition_done` (`mstar/graph/runtime/base.py:680`, called at `mstar/worker/worker.py:3468`) and the conductor at `mstar/conductor/conductor.py:1758`.
- **Keeps:** Chunks are ingested with `can_buffer=False` and only into a node that is streaming-ready, meaning all its non-streamed inputs have arrived (`mstar/worker/worker.py:1445`, `mstar/graph/runtime/python.py:523`). The final-chunk flag rides the synthetic edge into the node's slot so the consuming pass, not the ingest, reports the partition done, and only once every live stream into that partition has ended (`mstar/worker/worker.py:1439`, `:1653`).
- **Used by:** The worker main loop (`mstar/worker/worker.py:4564`, `:3177`), the speculative poll (`worker.py:1355`, used at `:2736` and `:2977`), the stream-terminated loop stop (`worker.py:3348`). Invariant 12 names Qwen3-Omni and Orpheus as the reference models.
- **Extend via:** A new stream is a `Connection` in `get_partition_topology`, a `StreamingGraphEdge` on the producer, and a consumer node that names the edge as an input. Cross-partition coordination follows Invariant 12. The `consumer_walk` hook it names is from #385 and is not on this main. The tempting duplicate is a second coordination path beside the one Invariant 12 describes, or a worker-side end-of-stream detector.
- **Breaks if:** A streaming-only `INPUT_SIGNALS` overwrites the partition's forward-pass info, which `mstar/worker/worker.py:1171` guards against. `StreamBuffer.ingested_chunk` holds one chunk, which is safe only because streaming ingest refuses buffering except for a speculative loop-back (`mstar/worker/worker.py:1390`). A walk that puts a self-triggered consumer beside other work is refused at startup (`mstar/model/base.py:564`).
