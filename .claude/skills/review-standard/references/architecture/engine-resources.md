# Engine and resources: mechanism map

Checkout: `main` at `fa381afd6`. "Invariant N" means section N of the "Invariants" in `AGENTS.md`.

Path short forms. `engine.py`, `accelerator_graph_runner.py`, `accelerator_graph_config.py` and `windowing.py` are under `mstar/engine/`. `runner.py`, `step.py`, `base.py`, `spec.py`, `convenience.py` and every `kv/`, `attn/`, `position/`, `sampler/`, `recurrent/` and `linear_attn/` path are under `mstar/engine/resources/`. `submodule_base.py` is `mstar/model/submodule_base.py`. `worker.py`, `micro_scheduler.py` and `engine_manager.py` are under `mstar/worker/`. Model paths are given in full.

Not on this main, though `AGENTS.md` names them: `get_chunking_policy`, `keep_final_chunk_samples` and `disable_spec_node_walks` (#365, about to merge), and `RecurrentStatePool.gather` / `scatter_` (open PR #383). A PR that adds one of these adds a mechanism. It does not duplicate one.

## Mechanisms

### Resource declaration and build
- **Does:** A model returns `NodeResourceSpec`s, the worker applies YAML overrides and startup refusals, and the engine builds one `Resource` per spec for the nodes it hosts and binds each node's subset into the submodule and its layers.
- **Where:** `spec.py:41` (`NodeResourceSpec`), `base.py:52` (`EngineResourceInfo`), `base.py:474` (`build_resource`), `engine.py:485` (`Engine.load_model`), `spec.py:129` (`apply_yaml_overrides`), `spec.py:108` (`resolve_spec_dependencies`), `submodule_base.py:532` (`bind_node_resources`).
- **Keeps:** One object per `resource_key`, built only when a local node names it, and each node maps to exactly the keys it declared (`engine.py:555-567`), which is invariant 2. A spec's `depends_on` is resolved into `EngineResourceInfo.dependencies` before it is built.
- **Used by:** `engine_manager.py:232-238` (declaration, overrides, startup refusals), `mstar/model/qwen3_5/qwen3_5_model.py:218` (a declaration), `mstar/model/components/attention.py:143` (a layer's `bind_resources` by `attn_key`, `kv_key`, `pos_key`).
- **Extend via:** A new `NodeResourceSpec` subclass with `resource_class`, `depends_on` and an explicit `apply_yaml_overrides`, plus a field on `EngineResourceInfo` for a new build-time fact. The duplicate to watch for is a submodule allocating persistent per-request state in `__init__` or `get_submodule`, or a Python sizing constant that belongs under `resources:` in the serving YAML.
- **Breaks if:** The `StepRunner` is built without some node in `node_resources`. That node falls back to the full sweep (`runner.py:96-100`), and `KVReqConfig.get_labels` answers `["main"]` for a node it does not know, which gates the node on another node's cache (`runner.py:345-349`, `kv/config.py:320-327`).

### Step declaration
- **Does:** Each step, the submodule's `declare_step` returns a frozen `SubmoduleStep` that maps resource keys to `ResourceStep`s made of `Segment(request_id, label, span)`, and the engine attaches the `StepContext`.
- **Where:** `submodule_base.py:640` (`declare_step`), `step.py:7` (`Segment`), `step.py:24` (`ResourceStep`), `step.py:120` (`SubmoduleStep`), `step.py:50` (`StepContext`), `engine.py:1482` (`_declare_and_admit`).
- **Keeps:** The declaration is frozen and only the engine sets its `_ctx` (`step.py:144-147`). `request_ids` pairs positionally with `inputs` and includes padding rows under a lease. A zero-span segment reads its stream without extending it (`step.py:8-14`).
- **Used by:** `engine.py:1498` (exec), `engine.py:2350` (pre-plan over template rows), `accelerator_graph_runner.py:801` and `accelerator_graph_runner.py:1105` (capture), `mstar/model/qwen3_5/submodules.py:468`, `mstar/model/bagel/submodules.py:1097` (forks).
- **Extend via:** A field on the resource's `ResourceStep` subclass, as `KVStep` carries `sink`, `fork_rids` and `retention` (`kv/config.py:473`), or a field on `StepContext` for a per-step fact the engine knows. The duplicate is a submodule that calls a resource's `plan` or `commit` itself, or returns None from `declare_step` and drives the resource as a facade (`submodule_base.py:655-656`), which opts it out of pre-plan and capture bookkeeping (invariant 1).
- **Breaks if:** The `cg_key_info` on the step disagrees with the one the slot was leased under, which raises at `engine.py:1588-1597`. A step that also declares a resource owned by a leased piecewise region (`ctx.piecewise_leases`, `submodule_base.py:668-670`) plans that resource twice.

### Admit, plan, forward, commit sweep
- **Does:** `StepRunner` drives a declared step through admit, plan and commit in dependency order, and `Engine.exec` wraps that around `preprocess` and the forward, as one batched or leased forward or as a per-request fallback.
- **Where:** `runner.py:58` (`StepRunner`), `runner.py:27` (`topo_sort`), `runner.py:428` (`admit`), `runner.py:479` (`plan`), `runner.py:560` (`commit`), `runner.py:468` (`rollback_admit`), `engine.py:1205` (`exec`), `engine.py:1275` (`_exec_single`), `engine.py:1366` (`_exec_per_request`), `engine.py:1563` (`_drive_step`), `engine.py:1680` (`_forward`), outcome types at `step.py:158-233`.
- **Keeps:** The order is the topological sort, computed once. Each resource's plan output is in `ctx.plan_results[key]` before a dependent plans. A refused admit unwinds every resource it reached in reverse order, the refuser included (`runner.py:457-463`, `runner.py:474-477`). `commit_done` is set right after commit and before output collection, and the plan thread waits on it (`engine.py:1324-1326`). `release_waiters` runs on every exit (`engine.py:1271`). The per-request fallback admits all rows first and rolls back the earlier ones if any refuses (`engine.py:1408-1414`).
- **Used by:** `worker.py:2171` (`exec_and_postprocess`), capture warm-up at `accelerator_graph_runner.py:1123-1128`, piecewise replay at `accelerator_graph_runner.py:2095-2101` and `accelerator_graph_runner.py:2244`. Refusals are routed at `worker.py:2254`: `AllocationFailed` goes to eviction (`worker.py:2321`), a `terminal` reason fails the request (`worker.py:2281`, `micro_scheduler.py:1283`), and anything else is re-queued (`worker.py:2285`).
- **Extend via:** The `Resource` hooks at `base.py:223-248`, with state for dependents returned from `plan`. A new refusal kind is an `AdmitFailedReason` subclass with the right `terminal` flag. A shortage should be `AllocationFailed` with `request_id` set, so a refusal with no eviction victim holds that one row (`worker.py:2384-2391`). The duplicates are a resource calling another resource's `plan`, a second ordering list, or an exception from `admit` or the forward for a condition the scheduler could resolve (invariant 1, heuristic 4).
- **Breaks if:** `rollback_admit` gives back more than the live reservation freshly took, such as pages retained from a shared prefix (`base.py:231-240`). KV refuses to unwind pages that are no longer its stream's tail and leaves the pool short (`kv/manager.py:1859-1867`).

### Readiness, retrieve and publish
- **Does:** `check_ready` reloads an offloaded request and then sweeps `admit_retrieve`, so each resource pulls in state another instance published, and after a step `finalize_batch` records what each resource publishes for the next node or worker.
- **Where:** `engine.py:2211` (`check_ready`), `engine.py:1865` (`finalize_batch`), `engine.py:1903` (`materialize_publish`), `engine.py:1930` (`finalize_stopped_requests`), `runner.py:337` (`admit_retrieve`), `runner.py:574` (`publish`), `runner.py:604` (`publish_snapshot`), `runner.py:646` (`publish_from_snapshots`), `runner.py:672` (`publish_after_stop`), hooks at `base.py:208` and `base.py:250-321`, `base.py:463` (`PublishedInfo`).
- **Keeps:** Both sweeps cover only the node's own resources, and only resources that override the hook (`runner.py:80-101`). Under `MSTAR_LAZY_PUBLISH` (on by default, `engine.py:85-90`) the snapshot is taken on the GPU thread at step time and finished later from the snapshot's lengths, not the live ones (`kv/manager.py:3185-3198`). Retrieved position counters only move forward (`position/manager.py:226-245`).
- **Used by:** `micro_scheduler.py:1282` (`check_ready`), `worker.py:2203`, `worker.py:3408-3409`, `worker.py:3669`. Implementations: `kv/manager.py:1487` (`admit_retrieve` with an async transfer), `kv/manager.py:3071` (`publish`), `kv/manager.py:3120-3232` (snapshot pair), `position/manager.py:206-245`.
- **Extend via:** A `PublishedInfo` subclass with `update` and `clone`, the `publish_snapshot_for_step` and `publish_from_snapshot` pair when publishing builds per-request objects, and `publish_after_stop` for state wanted only when a loop stops. `KVReqConfig.publish_labels_per_node_walk` selects which KV labels a step exports (`kv/config.py:238-245`). The duplicate is per-request bulk state carried in `step_metadata` or kwargs (invariant 6), or a transfer path inside one model.
- **Breaks if:** A resource overrides `publish_for_step` and not the snapshot pair. It stays correct, because the default snapshot calls the eager publish (`base.py:293-310`), but it pays a full publish per request per step, which is the cost the lazy path exists to remove. The readiness sweep is the hottest one (`runner.py:87-90`), so work added to `admit_retrieve` runs for every ready row on every scan (invariant 6).
- **See also:** `worker-scheduling.md` › Ready scan and engine readiness, `graph-runtime.md` › Ready scan, pop and push back.

### Pre-planning and slot double-buffering
- **Does:** The worker's plan thread leases step N+1's replay slot and runs admit and plan for the pre-planning resources on a side stream while step N replays, and the full sweep for N+1 later promotes what was staged.
- **Where:** `engine.py:123` (`SubmoduleManagement`, slot count at `engine.py:151-181`, `lease_slot` at `engine.py:200`), `engine.py:2239` (`reserve_replay_slot`), `engine.py:2282` (`can_pre_plan`), `engine.py:2295` (`pre_plan_for_batch`), `engine.py:2392` (`preplan_is_stale`), `engine.py:2399` (`reset_pre_plan_for_batch`), `runner.py:382` (`_step_key`), `runner.py:399` (`_drop_stale_preplan`), `runner.py:505` (`pre_admit`), `runner.py:539` (`pre_plan`), hooks at `base.py:329-353`.
- **Keeps:** A pre-plan writes only the leased slot, which the in-flight replay is not reading. A staged plan is promoted only by the step whose walk, padded rows, slot, capture key and segments all match, and any other step first clears the stage on every resource (`runner.py:370-414`). A pre-planning resource's dependencies must pre-plan too (`runner.py:233-248`). The slot counter is one per node, shared by its buckets and regions (`engine.py:134-137`).
- **Used by:** `worker.py:1941` (`_preplan_spec`, with calls at `worker.py:1961`, `worker.py:1977`, `worker.py:1984`, `worker.py:1999`), `worker.py:2140-2149` (stale check after `prepare_inputs`). Resource sides: `kv/manager.py:1685-1697`, `kv/manager.py:2379-2399`, `kv/manager.py:2479`, `attn/flashinfer.py:183-189`, `position/manager.py:257-291`, `sampler/resource.py:372-390`, `recurrent/pool.py:307-341`.
- **Extend via:** `supports_preplan`, a branch on `ctx.is_preplan` that writes a pending slot, and a `clear_preplan` that undoes every live-state effect of the staged admit, as KV removes labels it invented (`kv/manager.py:2489-2498`) and positions replay `_preplan_fork_undo` (`position/manager.py:262-270`). A resource that issues a non-blocking H2D out of a reused host buffer sets `force_double_buffer` (invariant 7). The duplicates are a resource keeping its own slot counter, stream or double buffer.
- **Breaks if:** Staging applies an effect the in-flight step can see. KV and the recurrent pool stage forks as pending state and copy only at promotion (`kv/manager.py:2401-2408`, `recurrent/pool.py:292-305`), and the sampler gathers per-step state at promotion rather than staging it (`sampler/resource.py:372-376`). A packed capture cannot be pre-planned, because a batch without inputs can lease only a batched bucket (`engine.py:2309-2314`, `accelerator_graph_runner.py:1324-1338`).
- **See also:** `worker-scheduling.md` › Pre-plan on the plan thread.

### Host-to-device staging
- **Does:** `mstar/utils/h2d.py` moves host values to the device without a stream drain: `to_device_nonblocking` copies one CPU tensor into a fresh pinned buffer and issues one non-blocking H2D, `PinnedStager` copies through a ring of persistent pinned buffers guarded by events, and `H2DMirror` lets a stager skip a copy whose values the destination already holds.
- **Where:** `utils/h2d.py:21` (`H2DMirror`), `utils/h2d.py:51` (`PinnedStager`), `utils/h2d.py:149` (`to_device_nonblocking`), at main 6690cff5.
- **Keeps:** A copy from pageable memory blocks the calling thread until it retires, so on the GPU thread it would wait out the step still running there. The pinned source stays alive until its copy retires (the caching host allocator for `to_device_nonblocking`, the ring's events for `PinnedStager`), and the device bits equal a pageable copy's.
- **Used by:** resources `kv/manager.py:636`, `kv/bounded/manager.py:82`, `recurrent/pool.py:209-212`, `sampler/resource.py:597`, `dsa/manager.py:187`, `attn/xpu.py:179`; models `components/diffusion/denoise_loop.py:178` and `:404` (the scaffold's seed and per-request schedule), `canary_qwen/submodules.py:71`, `components/audio_features.py:239-257`, `components/encoder_decoder.py:60`, `components/fastconformer_submodule.py:209`.
- **Extend via:** a call to `to_device_nonblocking` for a one-off host tensor in a model's step, or a `PinnedStager` (with an `H2DMirror` per fixed destination) for a resource's per-step arrays. The duplicate is a model-local `t.pin_memory().to(device, non_blocking=True)` helper (#963's `_to_device_without_sync` in `wan22/submodules.py`).
- **Breaks if:** A source buffer is reused before its non-blocking copy retires, so the copy reads the next step's values. `PinnedStager` waits on the buffer's event before rewriting it (`utils/h2d.py:132-136`), and a fresh pinned buffer per call avoids reuse altogether.

### Capture configs and bucket selection
- **Does:** A submodule declares `AcceleratorGraphConfig`s, and the runner expands them into buckets keyed by walk, batch size, token count and `cg_key_info`, sizes and plans the captures against free memory, captures the largest first, and leases the tightest bucket for each step.
- **Where:** `accelerator_graph_config.py:42` (`AcceleratorGraphConfig`), `accelerator_graph_config.py:100` (`BatchedAcceleratorGraphConfig`), `accelerator_graph_config.py:168` (`PackedAcceleratorGraphConfig`, with `make_node_input`, `capture_token_lengths`, `token_layout`), `step.py:29` (`BucketKey`), `accelerator_graph_runner.py:653` (`AcceleratorGraphRunner`), `accelerator_graph_runner.py:755` (`_get_slot_specs`), `accelerator_graph_runner.py:783` (`prepare_for_capture`), `accelerator_graph_runner.py:913` (`warmup_and_capture`), `accelerator_graph_runner.py:1301` (`select_bucket`), `accelerator_graph_runner.py:1324` (`select_batched_bucket`), `accelerator_graph_runner.py:1389` (`lease_slot`), `accelerator_graph_runner.py:503` (`plan_captures`), `engine.py:653` (`warmup`), `engine.py:731` (`_plan_captures`).
- **Keeps:** A bucket is registered only when every rank captured all of its slots (`accelerator_graph_runner.py:1016-1041`, invariant 11). Every runner claims its static buffers before any runner captures (`engine.py:674-680`). The lease names the capture walk, not the alias it was found under, so resources reuse the per-slot state the graph recorded (`accelerator_graph_runner.py:1413-1422`). Static inputs are interned per (config, key) at the largest bucket and sliced for smaller ones (`accelerator_graph_runner.py:1238-1282`).
- **Used by:** `engine.py:2263-2279` (lease), `engine.py:2128-2162` with `micro_scheduler.py:821-828` (scheduler grouping by capture key), `engine.py:2192-2209` with `micro_scheduler.py:1098` (batch cap from the largest bucket), configs at `mstar/model/qwen3_5/submodules.py:185` and `mstar/model/qwen3_omni/submodules.py:842`.
- **Extend via:** `get_accelerator_graph_configs` for a whole forward, `replay_graph_walks` for an alias, `additional_key_info` with a matching `cg_key_info` and `declare_step` for a second capture of one walk, `total_tokens_multiplier` for combined labels, `input_seq_dims` when the size-based seq-dim guess is wrong, and `caps_eager_batch_size=False` for a partial set of sizes. The duplicate is any raw capture call under `mstar/model/` (invariant 1).
- **Breaks if:** `cg_key_info()` and the step disagree, which misses the capture and runs eager with no error (`submodule_base.py:563-566`). `make_node_input` or `single_request_inputs` that do not match the shapes real `prepare_inputs` produces make the capture plan a different step from the one replay runs.
- **See also:** `worker-scheduling.md` › Capture groups, `lockstep.md` › 4. Capture agreement and per-spec barriers.

### Padding rows and sink storage
- **Does:** A replay pads the batch to its bucket with per-slot dummy rows that carry negative handles, run against a reserved sink page or slot, reserve and commit nothing, and have their outputs dropped.
- **Where:** `accelerator_graph_runner.py:564` (`DummyRowPool`), `accelerator_graph_runner.py:133-148` (`dummy_rid_handle`), `accelerator_graph_runner.py:1449` (`pad_inputs`), `accelerator_graph_runner.py:1463` (`step_ids`), `accelerator_graph_runner.py:1470` (`step_metadata`), `accelerator_graph_runner.py:1480` (`_stage`), `accelerator_graph_runner.py:1508` (`run_forward`), `accelerator_graph_runner.py:1536` (`release`), `step.py:73-114` (`set_padded_rids`, `is_real_row`, `is_padding_row`), `kv/plan.py:311` (`SINK_PAGE`), `recurrent/pool.py:39` (`SINK_SLOT`), `kv/manager.py:2472` (`_on_sink`), `kv/manager.py:409` (`KVPlanState.copy_`).
- **Keeps:** Real rows come first and padding follows. Padding rows, and every row of a capture, address the sink and hold no storage, so padding never competes with real requests (`kv/manager.py:1777-1783`, `recurrent/pool.py:216-228`, `accelerator_graph_runner.py:1539-1542`). Collected output row i belongs to `request_ids[i]` on both paths (`engine.py:1969-1971`, `engine.py:1992-1995`).
- **Used by:** `engine.py:1291-1298` (padding in `_exec_single`), `engine.py:2340-2347` (pre-plan), `engine.py:1950` (`_collect_outputs`), `kv/manager.py:1898-1907`, `kv/manager.py:2531`, `sampler/resource.py:360`, `recurrent/pool.py:405-413`.
- **Extend via:** A new resource tests `ctx.capture` or `ctx.is_padding_row(rid)` and points those rows at a sink reserved at construction, as KV does at `kv/manager.py:520-522`. `ingest_capture_row` (`base.py:201`) opens a padding row differently from a request. The duplicate is model code that pads or filters rows itself, or a resource that tracks its own list of dummy rows.
- **Breaks if:** A resource sizes per-request writeback by `padded_request_ids` where it means `request_ids`, which scatters padding rows back over real state (`accelerator_graph_runner.py:2068-2073`). A resource that allocates for padding rows fails on a near-full pool and holds the batch (`kv/manager.py:1777-1779`).

### Piecewise region capture
- **Does:** A submodule captures one inner callable, such as a block loop, as its own graph per (batch size, tokens, slot), and on each replay the region declares, admits, plans and commits its own resource step while the rest of the forward stays eager.
- **Where:** `accelerator_graph_config.py:270` (`PiecewiseAcceleratorGraphConfig`), `accelerator_graph_config.py:338` (`PiecewiseBatchedConfig`), `accelerator_graph_config.py:365` (`PiecewisePackedConfig`), `accelerator_graph_runner.py:1639` (`PiecewiseAcceleratorGraphRunner`), `accelerator_graph_runner.py:2061` (`_declare`), `accelerator_graph_runner.py:2166` (`lease_slot`), `accelerator_graph_runner.py:2179` (`run`), `engine.py:811` (`_build_piecewise_runners`), `engine.py:1532` (`_maybe_lease_piecewise_regions`), `engine.py:206` (`set_piecewise_slot`).
- **Keeps:** A node's regions share one graph memory pool and copy their outputs to buffers outside it (`engine.py:827-834`, `accelerator_graph_runner.py:210-241`). The regions capture in the order of the dict `get_piecewise_accelerator_graph_configs` returns (`engine.py:704` at e7d0315e), while `plan_captures` predicts the pool as if the largest went first (`accelerator_graph_runner.py:507-509`); each runner orders only its own shapes (`accelerator_graph_runner.py:1890-1904`). Kokoro's regions are ascending, and #657 reverse-sorts its dict to compensate. A region takes a second slot only if a resource its step touches sets `force_double_buffer` (`accelerator_graph_runner.py:1708-1725`). The slot is set on the GPU thread just before the forward, not at lease time (`engine.py:206-212`). Only the static buffers carry data into a replay (`accelerator_graph_runner.py:2192-2194`).
- **Used by:** `mstar/model/qwen3_5/submodules.py:823` (region `declare_step` at `mstar/model/qwen3_5/submodules.py:843`), `mstar/model/bagel/submodules.py:275`, `mstar/model/vjepa2/submodules.py:922`, `mstar/model/kokoro/submodules.py:378`, `mstar/model/qwen3_tts/submodules.py:879`.
- **Extend via:** `get_piecewise_accelerator_graph_configs` returning configs with `capture_fn`, `make_static_inputs` and `declare_step`, plus `lease_before_step` and `can_lease` when the outer declaration has to leave the region's resources out. The duplicate is a model capturing its own inner loop (invariant 1), or a region calling a resource's admit or plan itself.
- **Breaks if:** The region's Python reads per-step values at replay, since they were baked at capture. Reassigning a `static_inputs` entry detaches it from the address the graph holds (`accelerator_graph_config.py:254-256`).

### prepare_inputs and the uniform-row path
- **Does:** Before a forward the engine calls `prepare_inputs` per row, probes the prefix cache on keyed walks, drops rows that return None or raise, and asks `can_batch`, or for a walk whose inputs do not depend on the row it calls `uniform_row_inputs` once and shares that object across the rows.
- **Where:** `engine.py:927` (`prepare_inputs`), `engine.py:942` (`_prepare_inputs`, uniform path at `engine.py:964-977`), `engine.py:405` (`ExecutingBatch.drop_rids`), `submodule_base.py:720` (`uniform_row_inputs`), `submodule_base.py:704` (`can_batch`).
- **Keeps:** A raise fails only its row (`engine.py:1001-1007`), and None skips its row without an error (`engine.py:1008-1009`). The uniform path runs only for a step of one walk that is not keyed for prefix reuse (`engine.py:964`), and the shared object must not be mutated per row (`submodule_base.py:723-730`).
- **Used by:** `worker.py:2140`, `mstar/model/qwen3_5/submodules.py:332` (`uniform_row_inputs`), `mstar/model/qwen3_5/submodules.py:314` (`prepare_inputs`).
- **Extend via:** `uniform_row_inputs` for walks with row-independent inputs, a new field on `InputMetadata` for a new per-step input fact (`submodule_base.py:37-49`), and `input_seq_len` for token accounting. The duplicates are a submodule caching inputs across steps in a side dict, or the engine special-casing one model here (invariant 1, last paragraph).
- **Breaks if:** `prepare_inputs` syncs with the device or builds a device tensor from host data per row (invariant 7). Anything added here repeats for every backlogged row on every pass (invariant 6).

### Per-request submodule state
- **Does:** `PerRequestState` is an engine-owned store where a submodule keeps per-request objects across steps, reached through `request_state(rid)` in `prepare_inputs` and through `engine_inputs.per_request_states` in `preprocess` and the forward.
- **Where:** `submodule_base.py:349` (`PerRequestState`), `submodule_base.py:403` (`LazyRequestStates`), `submodule_base.py:586` (`request_state`), `submodule_base.py:980` (`cleanup_request`), `engine.py:1627` (injection), `engine.py:2660` (`Engine.remove_request`).
- **Keeps:** A request's state is dropped when the engine removes the request (`engine.py:2663-2664`), so handle-keyed state does not attach to a recycled handle (invariant 14). Padding rows get their own states, keyed by step id (`engine.py:1625-1627`).
- **Used by:** `engine.py:1627`, `engine_manager.py:326` (`remove_request`).
- **Extend via:** Per-request objects go in `request_state(rid)` rather than a private `dict[rid, ...]`. A submodule that still keeps other internal state overrides `cleanup_request` and calls super (`submodule_base.py:980-984`). The duplicate is a new handle-keyed dict on the submodule or the engine with its own purge.
- **Breaks if:** The state holds tensors derived from parameters that track gradients, which `load_model` prevents with `requires_grad_(False)` (`engine.py:573-577`). `disag_shared_keys` is reserved, and nothing on main transfers it (`submodule_base.py:362-365`).

### Device loopback of sampled tokens

## Discrepancies seen while reading

- `NodeSubmodule.get_autocast_dtype`'s docstring (`submodule_base.py:797-808`) says the engine consults it on each forward. On main it is read once at load to cast parameters (`engine_manager.py:280`), and the forward's autocast scope comes from `Engine._autocast_dtype_for` (`engine.py:649-651`), which reads only `disable_autocast`. An override changes the parameter dtype but not the autocast dtype the forward runs under.
- `NodeSubmodule.can_use_accelerator_graphs` (`submodule_base.py:850`) has no caller in the engine or worker. The engine's call to its predecessor `can_use_cuda_graphs` was removed in `2ce09185c` (#228) and not replaced. Six overrides across five models (orpheus, qwen3_omni, qwen3_tts, chatterbox, fish_s2_pro) refuse captures on batch shape, and only tests in `test/modular/` call them, so on main those refusals do not gate replay. I did not check whether bucket selection happens to cover each refusal.
- The module docstring of `spec.py:5-7` says a default declaration wraps a model's KV cache configs. `Model.get_node_resources` is abstract (`mstar/model/base.py:721`), so there is no default.
- `AcceleratorGraphRunner.lease_slot`'s docstring (`accelerator_graph_runner.py:1400-1402`) describes `slot=None` advancing a per-bucket counter. The parameter is a required int, and rotation is the node-wide counter in `SubmoduleManagement.lease_slot` (`engine.py:134-137`, `engine.py:200`).
- `fail_if_graphs_required`'s docstring names `MSTAR_REQUIRE_CUDA_GRAPHS`, but the code reads `MSTAR_REQUIRE_ACCELERATOR_GRAPHS` (`accelerator_graph_runner.py:244-254`).
