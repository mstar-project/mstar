# LingBot-VLA 2.0 port

This draft tracks the model port in [issue #828](https://github.com/mstar-project/mstar/issues/828). It does not add model serving yet.

The first implementation step reads the released checkpoint's `qwen3_vl` family marker and the separate Qwen3-VL base config. It streams the VLA checkpoint's vision and language weights into the existing shared Qwen3 towers. The released RoboTwin index has 315 vision tensors and 398 language tensors under that prefix; all vision names match the tower, and the language names map to its fused Q/K/V and gate/up parameters, with the output head tied to the input embedding.

The shared Qwen3 language tower now accepts the prefix's 3D position ids and applies interleaved MRoPE through its existing attention path. Tiny FP32 text and image-grid forwards match the Qwen3-VL text tower on both resource and array-state paths. This does not make the prefix runnable yet: the model graph still has to assemble image, text, and query tokens and declare their attention and KV state. The action expert, embodiment handling, and served request path follow as separate changes. Before choosing an attention or normalization path, compare the released RoboTwin checkpoint against the pinned reference at the prefix, denoising-step, and action outputs. Measure both FP32 and BF16 behavior and record the difference in the implementation PRs.

The suffix component reads the ten released state, action and timestep projection tensors, including `action_out_proj`. Its tiny FP32 and BF16-with-FP32-projections input rows match the pinned reference's `embed_suffix`, including the padding and segment attention masks. The output projection uses the reference's dtype rule on the decoded action rows. The action decoder is still separate work; no real checkpoint or served forward has been run.

The action decoder's MoE MLP uses the shared sigmoid correction-bias router, fused experts and shared MLP. The released RoboTwin index has the same eight MoE tensor keys on each of its 36 layers. A tiny CPU case matches the pinned eager reference in FP32 for routing, routed output, shared output and the sum; its BF16 forward has a maximum absolute gap of 0.0009765625. This is the MLP alone. The action tower's input and post-attention FiLM norms load the reference's separate RMS weight, gamma and beta tensors. The shared AdaRMSNorm uses a different gate and checkpoint layout, so this thin LingBot norm keeps the released semantics.

The action Q/K/V and output projections use the shared `ParallelAttention` linears and load the checkpoint's seven Qwen2 attention tensors per layer. They do not execute attention. The reference caches prefix K/V once per layer, then on each denoise step the state query reads all valid prefix keys and itself, while every action query reads those keys and the whole action block. This is the released RoboTwin config, whose suffix inputs have no padding and whose optional future-depth and future-video suffix blocking flags are both false. The existing state masks and dense prefix attention resource do not express that different reach for state and action queries in one read. A separate resource binding must join the cached prefix with the new suffix K/V, check that the prefix and action towers have the same K/V head geometry, cast their K/V and suffix Q to FP32 for MRoPE, and apply the mixed mask. The action output projection casts attended rows back to its weight dtype, as the reference does. Configs that enable future-depth or future-video blocking also need their prefix spans excluded. Until that lands, the action decoder, graph and serving path remain incomplete.
